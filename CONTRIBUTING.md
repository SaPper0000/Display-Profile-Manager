# Contributing

1. Create a branch for your change.
2. Keep changes focused and document user-visible behavior in `CHANGELOG.md`.
3. Do not add game-memory access, DLL injection, kernel drivers, packet manipulation, or gameplay automation.
4. Build the solution in **Release** configuration on Windows before submitting a pull request.
5. Verify that both Korean and English UI paths remain functional when changing shared UI code.
6. Do not commit `bin/`, `obj/`, `.vs/`, user settings, local paths, or generated debug artifacts.
